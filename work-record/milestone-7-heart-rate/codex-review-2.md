# Round 2 cross-review

**Verdict: do not merge or install.** The worst findings are regressions introduced by the round-1 fixes: contradictory rest alarms remain, source arbitration can persist a one-sample workout summary, minimize now retains an orphan session, and schema-v4 JSON drops the new estimated-zone provenance.

## Spec / behavior

1. **Critical — REGRESSION FROM ROUND 1 (2.3): contradictory alarms remain.** [HeartRateRest.swift:89](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HeartRateRest.swift:89>) still returns `.recovered` after the deadline when an older qualifying sample exists; [CodexReviewRegressionTests.swift:112](</Users/ericlee06/orca/projects/Health App/WorkoutTrackerTests/CodexReviewRegressionTests.swift:112>) now explicitly blesses that result despite saying the cap alarm already fired. [ActiveWorkoutView.swift:288](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/ActiveWorkout/ActiveWorkoutView.swift:288>) consequently schedules “recovered” after “time is up.” The new branch also changes a dead sensor with any earlier high sample from `.degraded` immediately before the deadline to `.cap` at the deadline. Before-deadline behavior is otherwise unchanged. **Implicates D43 and issue 01:57.**

2. **Critical — REGRESSION FROM ROUND 1 / unfixed 4.2: minimize loses ownership and creates a retain cycle.** [ActiveWorkoutView.swift:203](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/ActiveWorkout/ActiveWorkoutView.swift:203>) assigns a closure capturing the view and monitor to `HeartRateMonitor.onSample`, which the monitor strongly retains at [HeartRateMonitor.swift:174](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HeartRateMonitor.swift:174>). Minimize at [ActiveWorkoutView.swift:236](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/ActiveWorkout/ActiveWorkoutView.swift:236>) dismisses that owner without clearing or transferring it. Resume creates a second session and ultimately saves only the new monitor’s measurements; “Finish It & Start New” at [StartWorkoutView.swift:148](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/Start/StartWorkoutView.swift:148>) saves no vitals and cannot stop the old sensor. Users can get truncated history plus an orphan battery-draining session. **Implicates D41 and D44.**

3. **Critical — REGRESSION FROM ROUND 1 (1.1/5.1): schema-v4 JSON drops estimation provenance.** [ExportSnapshot.swift:175](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/ExportSnapshot.swift:175>) exports `zoneSeconds` but not `zonesFromEstimatedMax`; [ExportCollector.swift:250](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/ExportCollector.swift:250>) therefore loses it. A restore can turn historically estimated zones into unqualified facts. The new round-trip test only round-trips the already-lossy snapshot. **Implicates D30 and D45.**

4. **High — REGRESSION FROM ROUND 1 (2.1): degradation is not a stable fallback.** [RestTimer.swift:228](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/RestTimer.swift:228>) only changes the timer when the standard deadline is earlier than the HR cap. The UI permits a 5:00 standard rest and 4:00 cap, so that configuration never degrades and retains the false “didn’t reach target” cap alarm. If the standard deadline already passed, lines 234–246 schedule twice. The current rest also remains logically HR-mode, so a later sample can replace the standard fallback with a recovery. Finally, [RestTimerBar.swift:13](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/ActiveWorkout/RestTimerBar.swift:13>) has no degraded state, despite the ticket requiring the screen to say what happened. **Implicates D43.**

5. **High — a silent sensor death still cannot degrade while backgrounded.** `onSample` helps only when another sample arrives. Absence is detected solely by the SwiftUI timer at [ActiveWorkoutView.swift:206](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/ActiveWorkout/ActiveWorkoutView.swift:206>). If a sensor reports, dies after the screen backgrounds, and the standard deadline passes, the pre-scheduled HR cap fires instead. On foreground, `refreshRest` can clear the expired timer before degradation is evaluated. **Implicates D43’s explicit dropped-connection case.**

6. **High — REGRESSION FROM ROUND 1 (3.2): whichever sensor is current at Finish owns the entire workout.** [HeartRateMonitor.swift:128](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HeartRateMonitor.swift:128>) filters all historical samples to the source selected at that instant. After hours of AirPods data, one fresh Watch reading produces a one-sample persisted average/max; 16 seconds later the result flips back to AirPods-only history. Rest decisions can also retroactively reconsider old lower-precedence samples when the selected source changes. **Implicates D41, D44, and issue 04’s “two sources, one series.”**

7. **High — REGRESSION FROM ROUND 1 (1.2): production calories still disappear without HR samples.** [HealthKitHeartRateProvider.swift:150](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HealthKitHeartRateProvider.swift:150>) updates the provider’s energy total independently, but [HeartRateMonitor.swift:158](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HeartRateMonitor.swift:158>) copies that value only while ingesting a heart-rate sample. The corrected capture method therefore receives `nil` when energy arrives but BPM never does, and can persist a stale total when energy updates after the last BPM. **Implicates D41 and D44.**

8. **High — `+15s` breaks the HR cap contract.** [RestTimer.swift:287](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/RestTimer.swift:287>) extends `restEndsAt` and replaces the reasoned cap notification with the generic timer notification. The rule’s deadline at [HeartRateRest.swift:82](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HeartRateRest.swift:82>) remains the original configured cap, so readings during the extension cannot recover the rest and the eventual alarm no longer says why it ended. **Implicates D43.**

9. **High — max-HR configuration is unreachable on a fresh store and does not update the active workout.** The only entry point is the “zone estimated” button at [HeartRateBar.swift:94](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/ActiveWorkout/HeartRateBar.swift:94>), but that button appears only after a birth date already exists. With neither value—every migrated/new store—the sheet cannot be opened. If it is opened, [ActiveWorkoutView.swift:198](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/ActiveWorkout/ActiveWorkoutView.swift:198>) resolves the maximum only once, so saving a measured value leaves the live and persisted zones on the old basis. **Implicates D45.**

10. **High — persisted HR summaries are never shown in History.** [WorkoutDetailView.swift:11](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Features/History/WorkoutDetailView.swift:11>) renders only duration and sets; it never reads average HR, maximum HR, calories, zones, or estimation provenance. “View in History” therefore loses the summary immediately after the finish sheet closes. **Implicates D44 and the stated reason for persisting the summary.**

11. **High — queued workout-state messages can disrupt a newer Watch workout.** [WatchWorkoutModel.swift:207](</Users/ericlee06/orca/projects/Health App/WorkoutTrackerWatch/WatchWorkoutModel.swift:207>) parses the ID but never validates it against the current session. A delayed stop from workout A can stop workout B; a delayed start can overwrite B’s ID and cause all subsequent samples to be rejected by B’s phone provider. **Implicates D41.**

12. **High — the Watch’s advertised workout screen is incomplete.** Phone messages carry `restEndsAt`, but [WatchHeartRateProvider.swift:52](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/WatchHeartRateProvider.swift:52>) sends it only at start/stop and always as `nil`; no rest update is sent. [WatchRootView.swift:8](</Users/ericlee06/orca/projects/Health App/WorkoutTrackerWatch/WatchRootView.swift:8>) also omits the ticket’s zone and elapsed time. The wrist can never show its promised rest countdown. **Implicates D41/D43 and issue 04:11–12.**

13. **Medium — older Watch builds silently lose all HR after the round-1 fix.** [WatchHeartRateProvider.swift:108](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/WatchHeartRateProvider.swift:108>) rejects every sample without the new ID. That protects history from queued contamination, but contradicts the documented expectation that independently installed phone/watch builds will be version-skewed: upgrading either side alone produces “no sensor” with no explanation. The new Watch does set the ID before `start()` at [WatchWorkoutModel.swift:211](</Users/ericlee06/orca/projects/Health App/WorkoutTrackerWatch/WatchWorkoutModel.swift:211>), so the normal same-version first-sample path is correct. **Implicates D41.**

14. **Medium — non-Watch GATT sensors remain mislabeled as AirPods.** [HeartRateMonitor.swift:210](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HeartRateMonitor.swift:210>) hardcodes the phone source to `.airPods`, so a chest strap appears as AirPods. The round-1 number/label mismatch is fixed, but this separate part of 3.3 remains. **Implicates D41.**

15. **Medium — removing the cap fixes correctness but creates growing main-actor work.** Memory for roughly 10,800 samples over three hours is not material. The problem is that [HeartRateMonitor.swift:128](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HeartRateMonitor.swift:128>) filters the full workout on every sample, while [HeartRateRest.swift:103](</Users/ericlee06/orca/projects/Health App/WorkoutTracker/Domain/HeartRateRest.swift:103>) filters and sorts that history again during every active rest. Late-session rests can repeatedly sort thousands of samples on the main actor, creating avoidable UI/battery cost. **Implicates D41/D43.**
