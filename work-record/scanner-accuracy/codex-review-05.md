The library picker calls [`read(image)`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:115) without a region; that full-image JPEG is retained at [`ScanMachineLabelSheet.swift:509`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:509), advertised as “only the plate inside the box” at [`ScanMachineLabelSheet.swift:289`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:289), and sent at [`ScanMachineLabelSheet.swift:553`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:553). This violates D34 (“the whole frame never does”) and D53 (“only the plate inside the framing box is sent”) in [`docs/DECISIONS.md:42`](/Users/ericlee06/orca/projects/Health%20App/docs/DECISIONS.md:42). Invalid shutter geometry also fails open to the full frame.

- **Medium — hard violation:** Ask tasks have no retained cancellation/identity handle. [`restartScanning()`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:466) clears `asking`, and disappearance only abandons capture at [`ScanMachineLabelSheet.swift:126`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:126), so an HTTP request continues after rescan or dismissal. The [`current.crop == crop`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:562) checks suppress some results but compare byte contents, not request identity. An older task's [`defer { asking = false }`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:559) can also re-enable Ask while a newer request is active. This breaks D53's escalation gating.

- **Low — judgement call, Duplicated Code:** identical private `String.trimmed` helpers appear at [`PlateTranscription.swift:182`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Domain/PlateTranscription.swift:182) and [`AskAI.swift:198`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/AskAI.swift:198).

## Spec

- **High — whole library photo can leave the phone:** D53 says “only the plate inside the framing box is sent” and D34 says “the whole frame never does.” The picker supplies no region, and [`LabelCrop.pixelRect(nil, …)`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Domain/LabelCrop.swift:20) returns the whole image. This also contradicts the Settings disclosure, “not the whole photo,” at [`AskAISettingsSheet.swift:24`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Settings/AskAISettingsSheet.swift:24). Ticket resolution line 74 explicitly documents the library exception, so the resolution conflicts with D34/D53 rather than resolving it. The normal shutter path does map the non-nil box region into upright pixels; the full-frame exposure is the library path and fail-open geometry fallback.

- **High — rescans do not reliably isolate an ask:** ticket resolution lines 84–87 promise that one tap runs one call and a rescan drops an in-flight reply via “crop identity.” [`ask(_:)`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:553) launches an untracked task, while the supposed identity check is `Data` equality. Re-selecting the same library photo allows the old reply to land on the new results without a tap for those results. With different crops, an old task's `defer` can clear the newer task's `asking` gate and permit another concurrent paid request.

- **Medium — the client is not proxy-shaped as specified:** ticket line 32 requires “a base URL and a bearer, so a proxy is a config change.” The endpoint is configurable, but [`AnthropicPlateTranscriber`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/AskAI.swift:25) permanently writes the credential to `x-api-key`; an `Authorization: Bearer` proxy requires a source change.

- **Medium — the acceptance tests do not pin the safety claims:** ticket lines 47–52 require a counting client for the on-device-first invariant and UI coverage for offline, timeout, and refusal. There is no counting-client/injection test. [`AskAIUITests`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTrackerUITests/AskAIUITests.swift:64) covers only offline failure; timeout, refusal, 401, malformed, rescan, dismissal, and duplicate-call behavior are untested. Its “shutter” fixture calls [`read(ScanFixture.image())`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:244) with a nil region, so it does not prove shutter crop/orientation wiring. The unit tests cover rectangle arithmetic and a resize factor, not the pixels emitted by `LabelCrop.jpeg` from an EXIF-oriented image.

- **Medium — a fixture flag alone still activates fixture behavior:** the required invariant is that a fixture flag alone does nothing, but [`ScanFixture.isEnabled`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:620) checks only `-uiTestScanFixture` instead of `WorkoutTrackerStore.fixtureIsEnabled`. The new Ask AI fixture itself is correctly gated; the camera fixture used by these tests is not.

- **Low — the experiment baseline is not tied to the production prompt/schema:** ticket lines 50–51 require the LLM report to stay at or above the measured baseline whenever the prompt/schema changes. The production request at [`PlateTranscription.swift:98`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Domain/PlateTranscription.swift:98) removes `brand_from_logo_only`, while the experiment runner at [`work-record/scanner-accuracy/tools/llm_reader.py:37`](/Users/ericlee06/orca/projects/Health%20App/work-record/scanner-accuracy/tools/llm_reader.py:37) still uses the old schema/prompt. [`PlateTranscriptionTests.swift:34`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTrackerTests/PlateTranscriptionTests.swift:34) asserts only one prompt substring, so the checked-in LLM result does not pin the production contract.

## Checks that are clear

The normal call path is on-device first: [`MachineLabelOCR.read`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:508) finishes before results and the Ask button exist, and no call site invokes `transcribe` without the button action. Camera and AI readings both go through the same [`present(_:in:source:crop:)`](/Users/ericlee06/orca/projects/Health%20App/WorkoutTracker/Features/Gyms/ScanMachineLabelSheet.swift:525), `CatalogMatcher.rank`, and D33 preselection function; nothing applies without “Use This.” AI text is visibly echoed and can prefill create-new through that same reading path, but remains editable/confirm-gated rather than silently saved. The shutter crop is rendered upright, re-encoded without original metadata, and no image write-to-disk path exists. The key uses `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, is never logged or shown back, no key literal is present, and the UI-test memory slot is gated by `WorkoutTrackerStore.isUITestReset`. Offline/timeout/status/refusal/malformed errors all return to the existing results with a note and there is no retry loop; the defects above are request lifetime and missing proof, not basic error mapping.

Summary: **Standards — 4 findings** (worst: high, full-photo disclosure violation). **Spec — 6 findings** (worst: high, full-photo transmission and stale/concurrent asks).
